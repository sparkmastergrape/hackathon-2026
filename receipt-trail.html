The question

A settlement service that issues its own receipts is asserting that it paid someone. The receipt is only worth as much as the ability to check it without asking that service again.

So the test is narrow: take what the AP4M portal says, and find each piece of it in the ledger independently. If a claim ID appears in the portal and nowhere on chain, the receipt proves nothing.

What the method selector proves

The explorer labels the redemption transactions 0x21eb2efb. That label is only a lookup, so it was recomputed from the contract's own function signature rather than trusted:

keccak256("redeemVoucher((bytes32,uint256),bytes)")[0:4]
  = 0x21eb2efb        ← matches both transactions

The agent called the function it was supposed to call, on the contract AP4M publishes in its own /public/config.

The agent and payout wallets are different addresses, which AP4M requires: the party authorising a payment cannot be the party receiving it.

Reproduce it

The verifier takes an RPC endpoint from the environment, so none of this depends on the node used here, or on AP4M being available at all.

RPC_URL=<your node> node verify-receipt-onchain.mjs \
  0xcb1f2dabc921537530af35d8686b8aa21e3d8ce3fe9560823f79a471ffc33d9f

It reads the transaction receipt, confirms the destination is the PaymentLedger, decodes the claim and channel IDs from the event log, and finds the RLUSD transfer to the payout wallet in the surrounding blocks.

One trap worth knowing

The identifiers listed under Payments and receipts in the AP4M portal are claim IDs, not transaction hashes. Passing one to eth_getTransactionByHash returns null, which reads like a missing payment rather than a category error. The transactions were found by reading the agent wallet's own history, then matching the claim IDs in the emitted event logs.

Scope

This is XRPL EVM Testnet. The RLUSD here is a test token with no financial value, and the amounts are deliberately small. What the trail demonstrates is the shape of the evidence, not the size of the payment: an autonomous agent authorised a transfer, a contract recorded it, and the funds moved to a third party, with every step checkable by someone who trusts none of the parties involved.
